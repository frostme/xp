## What the numbers mean

The rule editor displays configured traffic coverage and variation weights. The Results tab draws on tracked exposures in the warehouse. A 10% weight describes how a qualifying evaluation is bucketed. To learn how many people qualified and were observed, the operator needs exposure data. Neither the editor nor the cited results screen establishes the current number of persisted memberships. [Exposure, variations and weights](https://docs.growthbook.io/features/feature-flag-experiments#exposure-variations-and-weights) · [Experiment results](https://docs.growthbook.io/features/feature-flag-experiments#experiment-results)

## Design findings

Four observed patterns inform this comparison.

1. Search results expose the identifier when the display name alone could mislead.
2. Creating a definition leads back to its detail screen, where the operator can review it before starting delivery.
3. The allocation change flow identifies which visitors a change affects before it is applied.
4. The finish form explains what the application will serve after submission.

**Weakness for xp’s operator (inference).** An operator reading “stopped” must also inspect temporary rollout and downstream rules to answer what a visitor sees. An xp detail view can answer that directly because the host’s decision contract defines a single winner, sticky cohort, or application default.

**Two transfers to xp.** First, take the operator from creation to the saved detail showing “Awaiting launch”, “Serving application default” and the pinned off cohort. The database read supplies the membership count. Second, put the effect on existing and new members directly above each confirmation. A split edit preserves current members, whereas selecting `checkout-copy_off` serves the default to everyone while retaining stored memberships. Show the selected cohort and the effect again on the saved detail.

**Outside this release.** GrowthBook’s warehouse-backed results and statistical recommendations require exposure and outcome data. xp can explain allocation and show present membership using its own database.
