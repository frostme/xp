# LaunchDarkly experiment iterations

Auditor 2 · LaunchDarkly research agent · 21 November 2026

**Access.** I traced the operator steps in LaunchDarkly’s public documentation. The references below point to the relevant screens and sections. I did not exercise an authenticated tenant or measure the time operators take to complete a task.

## Four observed patterns

1. **Scope precedes selection.** An environment section determines which instance a directory entry opens. A change affects only the selected environment. [Environment selection menu](https://launchdarkly.com/docs/home/experimentation/start-stop-exp#start-experiment-iterations)
2. **Saving and launching have distinct destinations.** A saved definition is discoverable from the list. Start is a separate action on its detail screen with its own confirmation. [Saving an in-progress design](https://launchdarkly.com/docs/home/experimentation/create#attributes)
3. **The commit step names the consequence.** An audience edit identifies the new iteration. Finishing first asks which variation the matching audience should receive. [Editing a running experiment](https://launchdarkly.com/docs/home/experimentation/edit-archive) · [Stopping an iteration](https://launchdarkly.com/docs/home/experimentation/start-stop-exp#stop-experiment-iterations)
4. **Counts have a defined unit.** The exposure graph describes unique contexts of the experiment’s randomization kind that encountered a variation over time. Repeating an evaluation for one user can leave the count at one. An operator can infer reach within that period. Current stored memberships and future weights require other data. [Exposures graph](https://launchdarkly.com/docs/home/experimentation/size#the-exposures-graph)

## Interpretation for xp

**One weakness.** The short label _Stop_ leaves the eventual serving behavior unresolved until the operator opens the shipping menu. Someone looking for a temporary pause could take the first step toward making a variation the winner. That is a design inference from the documented transition. [Stop flow](https://launchdarkly.com/docs/home/experimentation/start-stop-exp#stop-experiment-iterations)

- **Transfer 1 — distinguish pause from winner selection.** On the detail page for `checkout-copy`, use separate actions for pausing and selecting a winner. In the winner confirmation, name the selected cohort and explain that it will override existing assignments while their membership records remain in storage. Selecting `checkout-copy_off` serves the application default. Tie the same slug to the directory entry, detail and confirmation.
- **Transfer 2 — identify each number and its population.** In the split editor, show current and proposed percentages for future assignments and state that existing members keep their cohorts. On detail, label counts _Current memberships_. An operator should be able to see 100% off and zero memberships together before launch. Show a failed count read as unavailable with retry.
- **Outside xp’s scope.** Omit the estimator for how many more exposures a result needs to identify a winner. xp’s storage counts cannot support that inference. [Sample size estimator](https://launchdarkly.com/docs/home/experimentation/size#sample-size-estimator)
