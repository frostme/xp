# Optimizely Feature Experimentation

Independent audit by the Optimizely research agent, November 21, 2026. The evidence comes from public Feature Experimentation guides and their screen references. The operator sequence below is documented behavior. Access excluded the private console and a running test account.

## Operator walkthrough

| Task                 | Where it starts, what changes, and what the operator can check                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Discover and inspect | Pick a flag in the Flags directory and select its environment. The detail page identifies the environment’s ruleset and shows the status of the individual rule. A prepared rule can be waiting for its parent ruleset to run. Both statuses matter when interpreting the page. [Create an A/B Test rule](https://docs.optimizely.com/feature-experimentation/docs/run-a-b-tests-in-feature-experimentation) · [Flag management statuses](https://docs.optimizely.com/feature-experimentation/docs/flag-and-rule-lifecycle-management)                                                                                                     |
| Define               | Add an A/B rule, name it, check its generated key, choose variations and save. The rule starts in Draft. A variation menu allows an explicit comparison baseline. The SDK’s off decision returns false and can still contribute tracking data. [Configure your A/B test rule and Understand the Off variation](https://docs.optimizely.com/feature-experimentation/docs/run-a-b-tests-in-feature-experimentation)                                                                                                                                                                                                                          |
| Verify and launch    | The QA guide targets a test audience via an attribute and a targeted delivery rule so staff can check the integrated experience. The launch guide walks through enabling the rule and then its ruleset. When the parent is inactive, the intermediate confirmation explains why the rule is ready yet visitors cannot receive it. [QA audience setup](https://support.optimizely.com/hc/en-us/articles/38941239704589-Use-a-QA-audience-in-Feature-Experimentation) · [Rules UI updates](https://docs.optimizely.com/feature-experimentation/docs/flag-and-rule-lifecycle-management)                                                      |
| Change allocation    | The editor separates the percentage admitted to the experiment from how that group splits among variations. Manual distribution allows unequal percentages. The guide calls out the user profile service prerequisite for changing total traffic allocation during a run. An operator can also schedule a ramp for a specific flag, rule, environment and time. [Rule configuration](https://docs.optimizely.com/feature-experimentation/docs/run-a-b-tests-in-feature-experimentation) · [Create a scheduled change](https://support.optimizely.com/hc/en-us/articles/38908601122189-Manage-scheduled-changes-in-Feature-Experimentation) |
| Pause or finish      | An active rule has a Pause action in its overflow menu. Concluding ends editing. Choosing to deploy at conclusion lets the operator specify the variation, audience and traffic that will receive it, including returning visitors. The results page then marks the deployment. [Pause rules and Conclude rule](https://docs.optimizely.com/feature-experimentation/docs/flag-and-rule-lifecycle-management)                                                                                                                                                                                                                               |

**What counts convey.** Optimizely’s reporting guidance pairs dates with total visitors and visitors per variation. Those numbers describe the reported test population. A configured 5% share is a delivery setting. Neither quantity establishes how many current membership records an xp host holds. [What to share](https://support.optimizely.com/hc/en-us/articles/4410284001293-Share-your-results-with-stakeholders)

## Patterns and design judgment

1. The selected flag and environment identify the object a command affects.
2. The ready state explains why saving or enabling a rule can leave serving unchanged.
3. Labeling the denominator of each percentage distinguishes eligibility from the split among entrants.
4. Concluding with deployment names both the selected variation and the returning visitors affected.

**Weakness, inferred from the workflow.** A reader needs to combine the status of the rule with that of its parent to predict delivery. The same Run control can start traffic immediately or leave the rule waiting. xp can state the effective outcome in one sentence.

**Two transfers to xp.** First, put “Serving application default” beside the stored phase. For an off-first experiment, distinguish awaiting launch from a final off winner even when they return the same decision. Second, show the proposed split for new members and the unchanged stored memberships before applying a reweight. In the winner confirmation, explicitly name the cohort that existing members will now see and retain the count table after saving.

**Outside scope.** Targeting a QA audience by a profile attribute requires audience rules and host-side identity attributes. xp’s management page can explain the expected decision for existing and new members using the stored definition alone.
