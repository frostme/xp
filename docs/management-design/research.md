# Experiment management research

On 21 November 2026, five independent auditors traced the workflow in the default sample. GrowthBook provides inspectable self-hosted interface code. LaunchDarkly organizes delivery by environment. Statsig describes intentionally different endings. Optimizely connects a rule to its parent flag. PostHog joins a rollout editor to exposure reporting. These choices cover distinct operator tasks. Each report dates and links the public evidence, describes the access available and identifies design inferences.

| Audit                                  | Observed operator workflow                                                                          | Decision for xp                                                                                                                                  |
| -------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| [GrowthBook](audits/growthbook.md)     | Saved drafts open on detail; changing allocation can require a release plan for returning visitors. | Open the saved record after creation. Review the effect on existing members in the split editor.                                                 |
| [LaunchDarkly](audits/launchdarkly.md) | Start and stop name their environment and stop asks which variation to ship.                        | Keep the host-mounted context, experiment slug and proposed winner visible through confirmation. Give Pause its own action.                      |
| [Statsig](audits/statsig.md)           | Ending guidance compares newcomers and existing users. A 100% rollout can still be unshipped.       | Use the persisted phase for lifecycle labels. Review the consequence for each population.                                                        |
| [Optimizely](audits/optimizely.md)     | An enabled rule can be ready while the parent flag prevents delivery.                               | Put the effective decision above the saved phase and allocation. Keep the saved split visible when paused.                                       |
| [PostHog](audits/posthog.md)           | The editor validates the split at commit; exposure counts have a defined event and population.      | Show a total next to the editable inputs. Label current memberships and their read status, and show the share of future joins in its own column. |

Statsig locks the within-experiment split once the experiment starts. PostHog allows an allocation edit that can move users. GrowthBook offers policies for the affected audience. xp has a single storage contract: reweighting preserves every committed membership. The editor therefore explains how the proposed split applies to future joins. Winner selection has its own review because it overrides the served experience for both populations.

## Navigation and evidence

The directory identifies a record by name and slug. Its detail answers what a visitor sees and lists the current membership count for every cohort, including off. Each command returns to the committed detail. Mutations require host manage access, and the create route checks the host's separate creation setting. Staleness and retry states follow the xp revision contract. The [state table, fixtures and wireframe brief](brief.md) tie each surface to its allowed operations.

UX Pilot produced a [flowchart preview](../../review/experiment-management/ux-pilot-flow.json) from the brief. Its proposed `full_reweight` branch would imply moving existing users, so the wireframes use a single edit path. The design-system search in UI UX Pro Max suggested monospace identifiers, legible sans-serif body type, visible focus, reduced motion and responsive checks. Its focused UX and React queries recommended in-place validation, keyboard tab order, form submission semantics, dialog focus containment and focus return on close. We kept those. The initial search also proposed a showcase hero, orange CTA and animated blocks. None helps identify the outcome of a rollout in a host application.

Conversion lift, sample-ratio warnings derived from exposures, confidence intervals, automated recommendations and cumulative visitors would require different data. Current membership rows alone describe none of them. Scheduling, audience targeting and environment switching would require additional host contracts.
