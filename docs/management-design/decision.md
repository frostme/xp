## Selected direction

Use the Design proposal's title, phase and simple table hierarchy. Keep one directory route inside the host, as in the UX Pilot wireframes. Its rows answer what is served before an operator opens a detail. MagicPath's serving panel makes that answer prominent on detail. Use the two audience lines from Better Design and Figma to explain who receives which decision. Reuse Product Design's saved/proposed comparison in the full split review and stack labels beside each cohort on mobile. Name the recipient when a proposed weight reaches 100%.

Use a confirmation for a winner that names the cohort and explains what existing members and future visitors will see. Reweighting explains the different effect for existing members. A pause review names the saved phase that resume will restore. The palette uses a low-saturation green accent with explicit text for every state. The same tables and labels work without an analytics service or a host-specific navigation rail.

OpenPencil reported that its desktop app had no connected document. Figma supplied the additional editable vector proposal. UX Pilot provided its native flow preview and saved diagram. Its screen-generation widget requests the operator's **Start generating** click. The UX Pilot candidate documents which screens its author rendered locally. MagicPath's native canvas and local Chromium captures, Better Design's rules and local rendering, Product Design's three generated concepts, and Design's before/after inspection are linked in their respective reports.
